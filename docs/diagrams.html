dsh-sol 架构图和流程图

dsh-sol 是一个 DeepSeek Harness 插件，让 agent 用更少的 token 做完同样的活，而且不丢原始证据。思路来自 NVIDIA 的 SoL-Pi，按 DSH 自己的扩展点重写。所有模块默认关闭。2026-10-18 开发完成，2026-10-19 真机验证完成：5 个模块都在真实 DSH 里跑过，也测过和 dsh-ops 一起装，439 条测试全过（`npm test` 口径）。结果见 report.md 第 5 节。

1. 架构图

上半部分是 DSH 原生能力，插件不改它；下半部分是 dsh-sol 的模块。箭头上写的是挂接点。插件数据放在 $DSH_HOME/dsh-sol/<sessionId>/，不写 DSH 的会话日志。

2. 一步 Agent 循环里，各模块在哪里插手

左边是 DSH 原生流程，右边的虚线框是插件介入的位置。Meter 只观察：从会话日志读原生 tokenUsage，补上压缩那次的 token，每回合记一行，是证明“省没省”的依据。

3. Action Fusion：改完就测

改文件时顺带一条校验命令，改完立刻跑，两份结果一起返回，省掉一轮请求。没改成、文件被别处改过，命令都不跑。改文件和跑命令都是嵌套调用现有工具，照常走沙箱和审批；跑命令的 shell 按配置 shells 的顺序挑，默认先 ops_bash。命令没跑成（被拒、被策略拦下、没有可用 shell）时返回 [then_run:not_run] 和原因。

4. ObservationPack：大输出换成句柄

超过阈值的纯文本输出存进存档，上下文里只留固定的占位符；模型要细节时用 obs_recall 按页读回，各页拼起来和原文逐字节相等。模型从第一次起就只看到占位符。存的是后处理时收到的内容，和 ds-bot 同装时已经脱敏。增量主要在 10 KiB 到原生落盘阈值（约 12500 token）之间，做不做看计量数据。

5. Evidence-Preserving Reducer（可选）

失败的、超过 4 KiB 的 shell 输出交给便宜模型挑出关键原文，组成回执。不按命令名判断，正则清单总有漏网的。每条引文都要逐字核对，任何一步不通过就保留原结果。日志要外发，所以默认关闭。只处理没被截断的日志，不去读 shell 自己落盘的原始文件。

6. Online Context Compact：在步骤边界提前压缩

todo 里有步骤完成，并且上下文占用超过阈值（默认窗口的一半），就选一段旧历史压掉，回合不中断。v1 默认干跑：只在账本记“本来会压”，不真压，等真实数据定好阈值再打开。原来的“算账”（缓存重写成本、回本请求数）砍掉了，因为本机模型的缓存计价没核实。DSH 的 todo 没有 id，只能按文字对比步骤。只管非 Bot 会话：Bot 会话的压缩归 ds-bot 管。

7. 和 dsh-ops、ds-bot 共存

三个插件装在同一个 profile 里。dsh-sol 不关、不改另外两个，碰到的 7 个冲突点都在自己这一侧绕开，再用五条防护规则兜底。
